## 🧱 배타 락(Exclusive Lock) vs 공유 락(Shared Lock)

데이터베이스 시스템에서 **데이터 무결성과 일관성**을 보장하기 위해 사용되는 대표적인 잠금(Locking) 메커니즘인 **배타 락**과 **공유 락**에 대해 알아보겠습니다.

---

### 🔐 1. 개념 정리

| 유형         | 정의                                                                 | 사용 시점           | 다른 락과의 관계                     |
|--------------|----------------------------------------------------------------------|----------------------|--------------------------------------|
| **배타 락**   | 데이터를 읽거나 쓸 때, **다른 사용자로부터 완전히 차단**하는 락       | 업데이트, 삽입 등 쓰기 작업 | 공유 락이 있을 경우 **획득 불가**     |
| **공유 락**   | 데이터를 **읽기 전용**으로 사용할 수 있게 하며, 다른 사용자의 쓰기를 막음 | 읽기 작업 (SELECT 등) | 배타 락이 있을 경우 **획득 불가**     |

---

### 📌 2. 주요 차이점

| 항목         | 배타 락                              | 공유 락                              |
|--------------|---------------------------------------|----------------------------------------|
| 접근 허용    | 한 명의 사용자만 허용                | 여러 사용자에게 허용 (읽기만 가능)     |
| 사용 목적    | 데이터 수정 보호                     | 데이터 읽기 중 무결성 보장             |
| 충돌 처리    | 공유 락이 있을 경우 대기 or 실패     | 배타 락이 있을 경우 대기 or 실패       |
| 예시         | 계좌 잔액 갱신, 설정 변경             | 보고서 생성, 대규모 읽기 작업          |

---

### 👥 3. 예시 시나리오

#### 등장인물
- **Alice**: 계좌에 입금 (쓰기 → 배타 락 필요)
- **Bob**: 자신의 계좌 읽기 (읽기 → 공유 락)
- **Charly**: Bob의 계좌로 이체 (쓰기 → 배타 락 필요)

#### 시나리오 흐름
1. **Alice**가 자신의 계좌에 입금 → 배타 락 획득 성공
2. Alice는 입금 완료 후 트랜잭션 종료
3. Alice, 장기 보고서 작업 → 공유 락 획득
4. **Bob**도 보고서 작업 시작 → 공유 락 획득
5. **Charly**가 Bob의 계좌로 송금 시도 → 배타 락 실패 (Bob이 공유 락 중)
6. Bob이 작업 종료 후 → 공유 락 해제
7. Charly가 다시 시도 → 배타 락 획득 성공, 송금 완료

---

### ⚖️ 4. 장단점 비교

| 항목       | 장점                                              | 단점                                                  |
|------------|---------------------------------------------------|--------------------------------------------------------|
| **일관성 보장** | 읽기/쓰기 중 데이터 변경 방지                         | 동시성이 낮아지고, 시스템 사용률 저하 가능             |
| **안정성 확보** | 잘못된 값 읽기 및 쓰기 방지                           | 사용자가 많아질수록 락 충돌 가능성 증가                |

---

### 🏦 5. 활용 사례

- **은행 시스템**: 계좌 잔액의 정확한 업데이트 및 조회 보장  
- **중앙 설정 시스템**: 설정 변경 시 최신값 보장  
- **대규모 분석 시스템**: 장기 리포트 작업 중 데이터 안정성 유지

---

### ✅ 결론

- **배타 락**과 **공유 락**은 트랜잭션 간 **일관성(consistency)** 과 **무결성(integrity)** 을 보장하기 위한 핵심 도구입니다.
- 특히 **읽기/쓰기 충돌 방지**를 위해 잘 설계된 락 메커니즘은 동시 사용자 환경에서도 안정적인 데이터 처리를 가능하게 만듭니다.
