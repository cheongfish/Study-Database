# 데이터 일관성 (Consistency)

## 1. 데이터 일관성이란?

데이터 일관성(Consistency)은 **데이터베이스가 무결성을 유지하며 올바른 상태를 보장하는 속성**입니다. 
트랜잭션이 실행되기 전과 후에 데이터가 **일관된 상태를 유지해야 하며, 모든 무결성 제약 조건을 만족해야 합니다.**

### 1.1 데이터 일관성의 중요성
- **데이터 무결성 보장**: 트랜잭션이 실행되기 전후에 데이터가 무결성을 유지해야 함.
- **정확한 데이터 유지**: 잘못된 데이터가 반영되지 않도록 방지.
- **비즈니스 로직 준수**: 데이터가 예상치 못한 방식으로 변경되는 것을 방지.

## 2. 데이터 일관성의 종류

### 2.1 트랜잭션 일관성 (Transactional Consistency)
- **ACID 속성 중 하나**로, 트랜잭션 실행 전후의 데이터가 일관된 상태를 유지해야 함.
- **예시**: 은행 계좌 송금 시 A 계좌에서 돈이 빠지면, B 계좌에는 동일한 금액이 추가되어야 함.

### 2.2 읽기 일관성 (Consistency in Reads)
- 트랜잭션이 수행되는 동안 데이터가 **일관된 상태로 유지되는지 여부**를 의미.
- **예시**: 한 사용자가 특정 제품의 가격을 조회할 때, 조회하는 동안 가격이 변경되지 않아야 함.
- **캐시와 복제본을 사용하는 시스템에서는 읽기 일관성이 깨질 수 있음.**

### 2.3 분산 시스템에서의 일관성 (Distributed Consistency)
- **CAP 이론**에 따라 분산 시스템은 **일관성(Consistency), 가용성(Availability), 파티션 내성(Partition Tolerance)** 중 하나를 희생해야 함.
- **Eventual Consistency (최종 일관성)**:
  - 즉각적인 일관성을 보장하지 않지만, 일정 시간이 지나면 일관된 상태로 수렴.
  - NoSQL 데이터베이스에서 많이 사용됨 (예: Cassandra, DynamoDB).
- **Strong Consistency (강한 일관성)**:
  - 모든 노드가 항상 동일한 데이터를 조회하도록 보장.
  - RDBMS와 같은 트랜잭션 기반 시스템에서 사용됨.

## 3. 데이터 일관성을 보장하는 방법

### 3.1 트랜잭션과 ACID 속성
- 데이터 일관성을 유지하기 위해 데이터베이스는 **ACID 속성**을 지원해야 함.
- 트랜잭션이 실행될 때, 모든 제약 조건을 충족하는지 확인해야 함.

### 3.2 무결성 제약 조건 (Integrity Constraints)
- **참조 무결성 (Referential Integrity)**: 외래 키 제약 조건을 통해 부모-자식 관계를 유지.
- **도메인 무결성 (Domain Integrity)**: 특정 컬럼이 정의된 값 범위 내에서만 값을 가질 수 있도록 제한.
- **고유성 제약 (Uniqueness Constraints)**: 특정 컬럼 값이 중복되지 않도록 보장.

### 3.3 트랜잭션 격리 수준 조정
- 격리 수준을 조정하여 동시 실행되는 트랜잭션 간 **읽기 일관성**을 보장할 수 있음.
- **격리 수준과 일관성 관계**:
  - `Read Uncommitted`: 가장 낮은 일관성, Dirty Read 가능.
  - `Read Committed`: Dirty Read 방지, Non-Repeatable Read 발생 가능.
  - `Repeatable Read`: Non-Repeatable Read 방지, Phantom Read 발생 가능.
  - `Serializable`: 가장 높은 일관성 보장, 성능 저하 가능.

### 3.4 분산 시스템에서의 일관성 유지 기법
- **리더-팔로워(Leader-Follower) 복제**: 하나의 리더 노드에서 모든 쓰기 작업을 수행하고, 팔로워 노드에서 읽기 작업을 수행.
- **동기 복제(Synchronous Replication)**: 모든 노드가 동일한 데이터를 유지하도록 보장.
- **쿼럼(Quorum) 기반 접근**: 여러 노드에서 일정 개수 이상의 응답을 받아야 쓰기 또는 읽기를 수행함.

## 4. 데이터 일관성과 성능의 트레이드오프

- **강한 일관성(Strong Consistency)**을 유지하면 데이터의 신뢰성이 높아지지만, 성능이 저하될 수 있음.
- **최종 일관성(Eventual Consistency)**을 사용하면 성능을 높일 수 있지만, 읽기 시점에 따라 최신 데이터가 아닐 수 있음.
- 데이터베이스 선택 시 **비즈니스 요구사항에 따라 적절한 일관성 수준을 설정해야 함.**

## 5. 결론

- 데이터 일관성은 데이터베이스의 무결성을 유지하는 중요한 개념이며, 트랜잭션의 ACID 속성 중 하나.
- 트랜잭션 실행 전후에 데이터가 항상 일관성을 유지하도록 설계해야 함.
- 분산 시스템에서는 **강한 일관성과 최종 일관성 중 하나를 선택**해야 하며, 성능과 무결성 간의 균형을 맞춰야 함.
- **무결성 제약 조건, 트랜잭션 격리 수준, 복제 전략**을 활용하여 데이터 일관성을 유지할 수 있음.

데이터베이스 시스템을 설계할 때, **일관성 유지 전략을 올바르게 선택하는 것이 성능과 안정성에 큰 영향을 미친다**는 점을 항상 고려해야 합니다.
