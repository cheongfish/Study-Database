# ACID 퀴즈 및 문제 해결

## 1. 퀴즈

### **1. 트랜잭션이 성공적으로 커밋되었지만 이전에 시작된 다른 트랜잭션이 변경 사항을 확인할 수 없는 경우는 왜 발생할까요?**
✅ **정답:** 격리 수준이 `Repeatable Read` 이상으로 설정된 경우, 해당 트랜잭션은 실행 시작 시점의 스냅샷을 유지하므로 이후 변경 사항을 읽을 수 없음.

---

### **2. 원자성을 보장하는 트랜잭션 실행 방식은 무엇일까요?**
✅ **정답:**
- 모든 DML 문을 `BEGIN TRANSACTION`으로 시작하여 하나의 트랜잭션으로 실행한 후 `COMMIT` 해야 함.
- 실패 시 `ROLLBACK`을 수행하여 변경 사항을 취소.

---

### **3. 유령 읽기(Phantom Read)가 발생할 수 있는 SQL 쿼리는 무엇일까요?**
✅ **정답:**
- `SELECT * FROM employees WHERE salary > 5000;`
- 트랜잭션이 실행 중일 때 다른 트랜잭션이 `INSERT` 작업을 수행하면 기존 결과와 달라질 수 있음.

---

### **4. 비동기 복제를 사용하는 데이터베이스에서 발생할 수 있는 현상은?**
✅ **정답:**
- 빠른 쓰기 성능을 제공하지만, **최종 일관성(Eventual Consistency)** 만 보장됨.
- 복제본이 지연될 경우 최신 데이터를 조회하지 못할 수 있음.

---

### **5. 데이터베이스에서 지속성을 보장하는 OS 작업은?**
✅ **정답:** `fsync`
- 변경 사항을 OS 캐시가 아닌 디스크에 강제로 기록하여 데이터 손실을 방지함.

---

### **6. 트랜잭션 내에서 `UPDATE` 수행 후 `SELECT`를 실행하면 어떤 값이 반환될까요?**
✅ **정답:** 변경된 데이터 값이 반환됨.
- **격리 수준과 무관하게 트랜잭션 내에서는 항상 최신 변경 사항을 확인 가능**

---

## 2. 문제 해결

### **1. Dirty Read 문제 해결**
**문제:** 트랜잭션이 커밋되지 않은 데이터를 읽어 잘못된 정보를 처리할 가능성이 있음.
**해결 방법:** 격리 수준을 `Read Committed` 이상으로 설정하여 커밋되지 않은 데이터를 읽지 않도록 설정.

---

### **2. Non-Repeatable Read 문제 해결**
**문제:** 같은 트랜잭션 내에서 동일한 데이터를 조회할 때 값이 변경될 가능성이 있음.
**해결 방법:** 격리 수준을 `Repeatable Read` 이상으로 설정하여 트랜잭션 내 조회된 데이터가 변경되지 않도록 보장.

---

### **3. Phantom Read 문제 해결**
**문제:** 트랜잭션 중 범위 조회 시, 다른 트랜잭션이 데이터를 추가하거나 삭제하여 결과가 달라질 수 있음.
**해결 방법:** `Serializable` 격리 수준을 사용하거나 MVCC 기반 데이터베이스를 활용.

---

### **4. 손실된 업데이트(Lost Update) 문제 해결**
**문제:** 두 개의 트랜잭션이 동시에 동일한 데이터를 수정하면 한 트랜잭션의 변경 사항이 사라질 수 있음.
**해결 방법:**
- `SELECT ... FOR UPDATE` 사용하여 데이터 변경 시 잠금 적용.
- 애플리케이션 수준에서 버전 관리(Optimistic Locking) 사용.

---

### **5. 비동기 복제 환경에서 최신 데이터 보장 방법**
**문제:** 읽기 복제본이 최신 데이터를 반영하지 못할 가능성이 있음.
**해결 방법:**
- 강한 일관성을 보장하는 `Quorum Read` 전략 적용.
- 쓰기 후 읽기를 수행하는 경우 **주 서버에서 읽기(Read from Leader)** 설정.

---

### **6. 데이터 지속성 문제 해결**
**문제:** 장애 발생 시 트랜잭션 변경 사항이 손실될 가능성이 있음.
**해결 방법:**
- `WAL(Write-Ahead Logging)` 활성화하여 변경 사항을 먼저 로그에 기록.
- 정기적인 스냅샷(Checkpoint) 생성.

---

## 3. 요약

- **트랜잭션 격리 수준**에 따라 `Dirty Read`, `Non-Repeatable Read`, `Phantom Read` 문제가 발생할 수 있음.
- **격리 수준을 적절히 조정**하여 동시성 제어와 성능 간 균형을 유지해야 함.
- **비동기 복제 환경**에서는 최신 데이터 보장을 위한 추가 전략이 필요.
- **지속성을 위해 WAL 및 Checkpoint를 활용**하여 데이터 손실을 방지.
