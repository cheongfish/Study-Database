# 지속성 (Durability)

## 1. 지속성이란? (What is Durability?)

지속성(Durability)은 **트랜잭션이 성공적으로 커밋된 후에는 장애가 발생해도 데이터가 손실되지 않는 속성**을 의미합니다. 

트랜잭션이 커밋되면 변경된 데이터는 영구적으로 저장되며, 시스템 충돌이나 전원 장애가 발생하더라도 데이터를 복구할 수 있어야 합니다.

### 1.1 지속성이 중요한 이유
- **데이터 안정성 보장**: 저장된 데이터는 언제든지 다시 조회 가능해야 함.
- **트랜잭션의 신뢰성 향상**: 데이터가 손실되지 않도록 보장.
- **데이터베이스 복구 가능**: 장애 발생 후에도 정상 상태로 복구 가능.

## 2. 지속성을 보장하는 기술

### 2.1 로그 기반 저장 (Write-Ahead Logging, WAL)
- **트랜잭션 실행 전에 변경 사항을 먼저 로그에 기록한 후 적용하는 방식.**
- 장애가 발생해도 로그를 활용하여 데이터를 복구할 수 있음.
- PostgreSQL, MySQL(InnoDB), Oracle 등 주요 RDBMS에서 사용됨.

#### 2.1.1 WAL의 동작 방식
1. 트랜잭션이 시작됨.
2. 변경 사항을 로그(WAL)에 기록함.
3. 로그가 디스크에 저장된 후, 변경 사항이 실제 데이터베이스에 반영됨.
4. 시스템 장애 발생 시 로그를 이용해 데이터 복구 가능.

### 2.2 파일 시스템 동기화 (fsync)
- **fsync는 OS 캐시가 아닌 디스크로 데이터를 강제로 플러시(쓰기)하도록 요청하는 시스템 호출.**
- 데이터베이스 시스템이 커밋된 데이터를 디스크에 안전하게 저장하도록 보장함.
- 하지만, 성능 저하를 초래할 수 있어 적절한 조정이 필요.

### 2.3 비동기 스냅샷 (Asynchronous Snapshot)
- 특정 시점의 데이터 상태를 백업하여 보관하는 방법.
- 장애 발생 시 특정 시점으로 복원 가능.
- 고가용성 시스템에서 주로 사용됨.

### 2.4 AOF (Append-Only File)
- Redis와 같은 인메모리 데이터베이스에서 지속성을 보장하는 기법.
- 변경 사항을 순차적으로 로그에 기록하여 복구 가능.
- 주기적으로 압축하여 성능 최적화 가능.

## 3. 지속성과 성능의 트레이드오프

지속성을 보장하기 위해 데이터베이스는 디스크에 데이터를 저장하지만, **디스크 I/O는 성능 저하를 초래할 수 있음**. 

따라서, **성능과 지속성 사이의 균형을 유지하는 것이 중요**합니다.

| 기법 | 지속성 보장 수준 | 성능 영향 |
|------|---------------|---------|
| WAL (Write-Ahead Logging) | 높음 | 중간 |
| fsync | 매우 높음 | 높음 (성능 저하 가능) |
| 비동기 스냅샷 | 중간 | 낮음 (백그라운드에서 실행) |
| AOF (Append-Only File) | 높음 | 중간 |

## 4. 장애 발생 시 복구 방법

- **Redo 로그 활용**: WAL을 이용해 장애 발생 후에도 변경 사항을 재적용.
- **Checkpoint 사용**: 주기적으로 데이터베이스의 스냅샷을 저장하여 빠른 복구 가능.
- **Replication(복제) 활용**: 데이터베이스 복제를 통해 고가용성 보장.

## 5. 결론

- 지속성(Durability)은 트랜잭션의 변경 사항이 영구적으로 유지되도록 보장하는 ACID 속성 중 하나.
- WAL, fsync, 스냅샷, AOF 등의 기법을 활용하여 지속성을 보장할 수 있음.
- 성능과 지속성 사이의 균형을 맞추는 것이 중요하며, 데이터베이스 환경에 따라 적절한 기법을 선택해야 함.
