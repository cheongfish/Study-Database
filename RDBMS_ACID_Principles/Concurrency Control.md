# 동시성 제어 (Concurrency Control)

## 1. 동시성 제어란?

동시성 제어(Concurrency Control)는 다수의 트랜잭션이 동시에 실행될 때, **데이터의 무결성을 유지하면서 동시 실행을 조정하는 기법**입니다. 

### 1.1 동시성 문제
다중 트랜잭션이 동시에 실행되면 다음과 같은 문제가 발생할 수 있습니다.

- **Dirty Read (더티 리드)**: 커밋되지 않은 데이터를 다른 트랜잭션이 읽음.
- **Non-Repeatable Read (비반복 읽기)**: 동일 데이터를 반복해서 읽을 때 값이 달라짐.
- **Phantom Read (팬텀 리드)**: 트랜잭션 실행 중, 새로운 행이 추가되거나 삭제되어 쿼리 결과가 달라짐.
- **Lost Update (손실된 업데이트)**: 두 개의 트랜잭션이 같은 데이터를 수정할 때, 한 트랜잭션의 변경 사항이 덮어씌워짐.

## 2. 동시성 제어 방식

### 2.1 비관적 동시성 제어 (Pessimistic Concurrency Control)
- 데이터 충돌을 **사전에 방지**하기 위해 잠금(Locking) 기법을 사용.
- 한 트랜잭션이 데이터를 수정하는 동안 다른 트랜잭션이 접근하지 못하도록 차단.
- **잠금의 종류**:
  - **공유 잠금(Shared Lock, S Lock)**: 데이터를 읽을 때 사용, 여러 트랜잭션이 동시에 읽기 가능.
  - **배타적 잠금(Exclusive Lock, X Lock)**: 데이터를 수정할 때 사용, 한 트랜잭션만 접근 가능.
- **장점**: 데이터 무결성을 강력하게 보장.
- **단점**: 성능 저하(데드락 발생 가능, 동시성이 제한됨).

#### 2.1.1 잠금 단계 (Lock Escalation)
- **행(Row) 잠금**: 특정 행만 잠금, 동시성 높음.
- **페이지(Page) 잠금**: 특정 페이지(블록) 단위로 잠금.
- **테이블(Table) 잠금**: 전체 테이블 잠금, 동시성 낮음.
- **잠금 상승(Lock Escalation)**: 너무 많은 행 잠금을 사용하면 데이터베이스가 성능 최적화를 위해 페이지 또는 테이블 수준으로 잠금을 확장함.

### 2.2 낙관적 동시성 제어 (Optimistic Concurrency Control)
- 데이터 충돌을 **사후에 감지**하고 해결하는 방식.
- 트랜잭션이 데이터 변경을 완료한 후, 충돌이 없는 경우 커밋하고, 충돌이 발생하면 롤백.
- 주로 **읽기 작업이 많고 쓰기 작업이 적은 환경에서 사용**.
- **장점**: 잠금 비용이 없으므로 성능 향상 가능.
- **단점**: 충돌 발생 시 롤백 비용이 증가.

#### 2.2.1 MVCC (Multi-Version Concurrency Control)
- 트랜잭션이 데이터를 수정할 때 기존 데이터를 변경하는 것이 아니라 **새로운 버전을 생성**.
- 기존 트랜잭션은 원래 데이터를 유지하며, 새로운 트랜잭션은 최신 버전을 사용.
- **특징**:
  - **더티 리드 방지**: 트랜잭션이 커밋되지 않으면 새로운 버전이 노출되지 않음.
  - **고립성(Isolation) 보장**: 한 트랜잭션이 변경한 데이터를 다른 트랜잭션이 즉시 볼 수 없음.
  - **PostgreSQL, MySQL (InnoDB) 등에서 사용됨**.

### 2.3 직렬화 동시성 제어 (Serializable Concurrency Control)
- 트랜잭션을 **순차적으로 실행한 것과 동일한 결과를 보장**.
- **트랜잭션 스케줄링 방식**:
  - **락 기반 직렬화 (Lock-Based Serialization)**: 트랜잭션이 직렬 실행되도록 잠금을 사용.
  - **타임스탬프 기반 직렬화 (Timestamp-Based Serialization)**: 각 트랜잭션에 타임스탬프를 부여하여 실행 순서를 결정.
- **장점**: 완전한 데이터 일관성 보장.
- **단점**: 성능 저하(병렬 실행 불가능, 처리 속도 느림).

## 3. 동시성 제어 방법 비교

| 방법 | 적용 방식 | 장점 | 단점 |
|------|----------|------|------|
| **비관적 동시성 제어** | 잠금 (Locking) 사용 | 데이터 무결성 보장 | 데드락 가능성, 성능 저하 |
| **낙관적 동시성 제어** | 충돌 감지 후 해결 | 성능 향상, 동시성 증가 | 충돌 시 롤백 비용 증가 |
| **MVCC** | 버전 관리 | 동시성 증가, 읽기 성능 우수 | 저장 공간 증가 |
| **직렬화** | 트랜잭션 순차 실행 | 완벽한 일관성 | 성능 저하 |

## 4. 동시성 문제 해결 전략

- **비관적 동시성 제어 사용**: 트랜잭션 충돌이 빈번한 경우.
- **낙관적 동시성 제어 사용**: 읽기 작업이 많고 충돌 가능성이 적은 경우.
- **MVCC 사용**: 트랜잭션의 일관성과 동시성을 동시에 보장할 필요가 있는 경우.
- **직렬화 적용**: 완벽한 데이터 무결성이 요구되는 경우(예: 금융 시스템).

## 5. 결론

동시성 제어는 데이터 무결성과 성능을 균형 있게 유지하는 중요한 기법입니다. **어떤 동시성 제어 방식을 사용할지는 애플리케이션의 특성과 요구 사항에 따라 달라집니다.** 

- **비관적 동시성 제어**는 **데이터 충돌을 사전에 방지**하지만 성능이 저하될 수 있음.
- **낙관적 동시성 제어**는 **충돌을 사후에 해결**하며, 읽기 위주의 시스템에서 유리함.
- **MVCC**는 **읽기 성능을 향상**시키는 방식이며, PostgreSQL과 MySQL에서 널리 사용됨.
- **직렬화 방식**은 **완벽한 데이터 일관성을 보장**하지만 성능이 저하될 수 있음.

따라서, **비즈니스 로직과 데이터베이스 환경에 맞는 동시성 제어 전략을 선택하는 것이 중요합니다.**
