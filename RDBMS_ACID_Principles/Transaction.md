# 트랜잭션 개요

## 1. 트랜잭션(Transaction)이란?

트랜잭션은 **하나의 논리적 작업 단위**로, 데이터베이스의 일관성과 무결성을 보장하기 위해 ACID 특성을 따릅니다.

### 1.1 트랜잭션의 특징
- **원자성(Atomicity)**: 모든 연산이 성공적으로 수행되거나, 하나라도 실패하면 전체가 롤백됨.
- **일관성(Consistency)**: 트랜잭션 실행 전후에 데이터 무결성이 유지됨.
- **격리성(Isolation)**: 여러 트랜잭션이 동시에 실행될 때, 서로 영향을 미치지 않아야 함.
- **지속성(Durability)**: 커밋된 트랜잭션의 변경 사항은 영구적으로 저장됨.

## 2. 트랜잭션의 실행 구조

트랜잭션의 기본 실행 흐름은 다음과 같습니다:

```sql
BEGIN;
  -- 여러 개의 SQL 문 실행
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

- **BEGIN**: 트랜잭션 시작
- **SQL 실행**: 여러 개의 데이터 변경 연산 수행
- **COMMIT**: 트랜잭션을 성공적으로 종료하고 변경 사항 반영
- **ROLLBACK**: 오류 발생 시 트랜잭션을 취소하고 변경 사항을 무효화

## 3. 트랜잭션의 종류

### 3.1 사용자 정의 트랜잭션
- 사용자가 직접 정의하여 실행하는 트랜잭션
- 주로 비즈니스 로직에 따라 여러 개의 SQL 명령어를 포함

### 3.2 시스템 트랜잭션
- 데이터베이스 시스템 내부에서 자동으로 수행하는 트랜잭션
- 예: 자동 복구 트랜잭션, 시스템 유지보수 트랜잭션

## 4. 트랜잭션의 주요 개념

### 4.1 트랜잭션의 원자성 (Atomicity)
- 트랜잭션 내의 모든 작업이 성공해야 하며, 하나라도 실패하면 전체가 롤백됨.
- 충돌이 발생하면 롤백을 수행하여 데이터의 무결성을 유지.

### 4.2 트랜잭션의 실행 방식
- 즉시 반영(Autocommit): 트랜잭션 없이 각 SQL 실행 후 자동으로 커밋.
- 명시적 트랜잭션: `BEGIN`과 `COMMIT`을 사용하여 명시적으로 트랜잭션을 제어.
- 일괄 처리(Batch Processing): 여러 트랜잭션을 한꺼번에 처리하여 성능 향상.

## 5. 트랜잭션과 격리 수준(Isolation Level)

트랜잭션의 격리 수준은 여러 트랜잭션이 동시에 실행될 때 서로 간섭을 얼마나 허용할지를 결정합니다.

| 격리 수준 | 설명 | 문제점 |
|-----------|------------------------------------------------|------------------|
| **Read Uncommitted** | 커밋되지 않은 데이터를 읽을 수 있음 | Dirty Read 발생 |
| **Read Committed** | 커밋된 데이터만 읽을 수 있음 | Non-Repeatable Read 발생 |
| **Repeatable Read** | 같은 데이터를 여러 번 읽어도 동일한 결과 보장 | Phantom Read 발생 가능 |
| **Serializable** | 트랜잭션을 직렬화하여 실행 | 성능 저하 |

## 6. 트랜잭션 롤백과 스냅샷

### 6.1 롤백(Rollback)
- 트랜잭션 도중 오류가 발생하면 데이터베이스를 원래 상태로 되돌림.
- 예: `ROLLBACK;`

### 6.2 스냅샷(Snapshot)
- **MVCC(Multi-Version Concurrency Control)** 기법을 활용하여 트랜잭션이 실행될 때의 데이터 상태를 저장.
- 특정 시점의 데이터를 유지하면서 일관성을 보장함.

## 7. 트랜잭션 사용 시 고려 사항

- **트랜잭션 크기 조절**: 너무 긴 트랜잭션은 교착 상태(Deadlock)를 유발할 수 있음.
- **적절한 격리 수준 선택**: 성능과 데이터 일관성 간의 트레이드오프 고려.
- **자동 커밋 설정 관리**: 필요하지 않은 경우 자동 커밋을 비활성화하여 제어력 향상.

## 8. 결론

트랜잭션은 데이터베이스에서 **데이터 일관성**과 **무결성**을 유지하는 핵심 요소입니다. 적절한 격리 수준을 설정하고, 트랜잭션 크기를 조절하여 최적의 성능을 유지하는 것이 중요합니다.
