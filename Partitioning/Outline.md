### 1. 파티셔닝(Partitioning)의 개념

- **정의**: 대용량 테이블을 **논리적으로 더 작은 단위(파티션)**로 나누는 기술.
- **목적**:
  - 쿼리 성능 향상
  - 데이터 관리 용이
  - 데이터 분산 및 병렬 처리 가능

---

### 2. 파티셔닝이 왜 필요한가?

- **문제 상황**: 고객 테이블에 100만 개의 행이 있을 때, 다음과 같은 쿼리를 실행한다고 가정:
  ```sql
  SELECT Name FROM CUSTOMERS_TABLE WHERE ID = 700001;
  ```
- **비효율 시나리오**:
  - 인덱스 없음 → 전체 테이블 스캔 → 매우 느림
  - 인덱스 있음 → 여전히 대용량 탐색 부담 존재

---

### 3. 파티셔닝의 작동 원리

- **CUSTOMERS 테이블을 5개 파티션으로 나눔**
  - ID 범위: 1~200,000 / 200,001~400,000 / ... / 800,001~1,000,000
- **메인 테이블 = 부모(Parent), 실제 데이터 = 자식(Child) 파티션에 저장**
- **DB는 조건에 맞는 파티션만 조회**하여 성능을 극대화함

예시:
```sql
SELECT Name FROM CUSTOMERS_TABLE WHERE ID = 700001;
```
→ 600,001~800,000 파티션만 스캔 → 검사 행 수 20만 개로 감소 → 처리 속도 향상

---

### 4. 파티셔닝 방식 비교

#### ✅ 수평 분할 (Horizontal Partitioning)

| 항목 | 내용 |
|------|------|
| 정의 | **행 단위**로 나누는 방식 |
| 예시 | ID 1~1000 → 파티션 A<br>ID 1001~2000 → 파티션 B |
| 장점 | 쿼리 성능 향상, 파티션 단위 병렬 처리 가능 |
| 구현 | `PARTITION BY RANGE`, `PARTITION BY LIST` 등 사용 |

- 예: 우편번호 기준 분할 → 90205 → A 파티션, 91111 → B 파티션

#### ✅ 수직 분할 (Vertical Partitioning)

| 항목 | 내용 |
|------|------|
| 정의 | **열 단위**로 나누는 방식 |
| 예시 | BLOB 열을 별도 테이블로 분리 |
| 장점 | 디스크 공간 절약, 캐시 효율 증가 |
| 구현 | 자주 쓰이는 열만 메인 테이블에 남김 |

- 필요한 열이 있을 때만 별도 테이블에서 JOIN

---

### 5. 실무 적용 전략

- **파티셔닝 + 인덱스 = 최적의 조합**
- 가능한 한 **쿼리 조건이 파티션 키와 맞도록 설계**
- 자주 쓰지 않는 데이터는 수직 분할하여 **핵심 테이블을 슬림하게 유지**
- 파티션 수가 너무 많아도 성능 저하 유발 → 적절한 균형 유지 필요

---

### 🔑 핵심 원칙 정리

- "**가장 빠른 쿼리는, 읽지 않아도 될 데이터를 읽지 않는 것**"
- 파티셔닝은 단순 저장 구조가 아니라 **쿼리 계획 최적화의 도구**
- 데이터 규모가 커질수록 파티셔닝의 효과는 기하급수적으로 커진다
