# 데이터베이스 샤딩과 수평 분할

## 📌 전통적인 데이터베이스 구조

기존에는 하나의 중앙 집중식 데이터베이스에 모든 데이터를 저장하는 방식이 일반적이었습니다. 이 데이터베이스에는 여러 테이블이 존재하고, 각각은 인덱스를 통해 빠른 조회를 지원합니다.

하지만 데이터가 증가하면:

- 테이블과 인덱스가 커지고
- 쿼리 성능이 저하되며
- 더 많은 메모리, CPU, 디스크 I/O가 필요하게 됩니다.

예:  
URL 단축기 서비스에서는 수백만 개의 URL과 고유 코드가 있는 하나의 테이블이 존재합니다. 특정 코드를 통해 URL을 조회하는 쿼리는 데이터가 많아질수록 점점 느려지게 됩니다.

---

## 📌 샤딩(Sharding)이란?

샤딩은 **하나의 테이블을 여러 개의 데이터베이스로 분산 저장**하는 방식입니다.

- 특정 키(Sharding Key)를 기준으로 데이터를 분할
- 예: 100만 개의 URL을 20만 개씩 5개의 DB에 분산

### 장점
- 데이터 증가에 따라 서버를 추가하여 확장 가능 (수평 확장)
- 특정 서버에만 쿼리를 전송하므로 부하 감소

---

## 📌 샤딩 키 예시

- **사용자 ID 기준**  
  - ID 1~5억 → DB1  
  - ID 5억~10억 → DB2

- **지역 기준**  
  - 우편번호 동부 → DB1  
  - 우편번호 서부 → DB2

복잡한 키(문자열 등)일 경우에는 어떤 서버에 저장할지를 판단하기 위해 **일관성 해싱**을 사용합니다.

---

## 📌 일관성 해싱 (Consistent Hashing)

입력값을 해시하여 어떤 서버로 보낼지 결정하는 방식입니다.

예: 3개의 DB 인스턴스

- 입력값 10 → `10 % 3 = 1` → 서버 5433
- 입력값 12 → `12 % 3 = 0` → 서버 5432

### 특징
- 동일한 입력은 항상 동일한 서버로 연결됨
- 예측 가능하고 안정적인 데이터 분산 가능
- 해시 결과에 따라 `해시 링(Hash Ring)` 구조를 활용할 수 있음
- Cassandra 같은 분산 시스템에서 사용

---

## 📌 수평 분할 vs. 샤딩

| 구분           | 수평 분할 (Horizontal Partitioning)             | 샤딩 (Sharding)                                      |
|----------------|--------------------------------------------------|------------------------------------------------------|
| 위치           | 동일한 데이터베이스 내                           | 서로 다른 데이터베이스 서버                          |
| 구조 변경      | 테이블 이름/스키마가 달라짐 (`customers_east`)   | 테이블 이름은 동일, 물리적 위치만 분산               |
| 확장성         | 제한적                                           | 높은 확장성                                          |
| 목적           | 내부 관리 목적의 분할                             | 성능 향상과 분산 저장 목적                           |

---

## 📌 정리

- 데이터가 증가하면 단일 DB로는 한계에 도달합니다.
- 샤딩은 데이터를 여러 DB에 분산시켜 성능과 확장성을 확보합니다.
- 일관성 해싱을 통해 입력값에 따라 올바른 DB를 선택할 수 있습니다.
- 수평 분할과 샤딩은 유사하지만, **물리적인 분산 여부**가 핵심 차이입니다.
