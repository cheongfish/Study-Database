# 데이터베이스 샤딩(Sharding)의 개념 및 장단점 정리

## 📌 샤딩이란?
샤딩은 대규모 데이터를 처리하기 위해 데이터를 여러 개의 데이터베이스 서버(샤드)로 분산하는 **수평 파티셔닝 전략**입니다. 각 샤드는 전체 데이터의 일부분만을 저장하며, 클라이언트는 샤딩 키를 기준으로 어떤 샤드에 접근해야 할지 결정합니다.

---

## ✅ 장점

### 1. 확장성 (Scalability)
- 데이터를 여러 서버에 분산시켜 **수평 확장(horizontal scaling)** 이 가능합니다.
- CPU, 메모리, 저장소 등의 리소스가 하나의 서버에 집중되는 것을 방지합니다.
- 서버 수를 늘리는 것만으로도 더 많은 데이터를 효율적으로 처리할 수 있습니다.

### 2. 성능 향상
- 샤드당 데이터량이 줄어들면서, **인덱스 크기가 작아지고**, 이에 따라 쿼리 속도가 빨라집니다.
- 동시 처리량도 증가합니다.

### 3. 보안 및 접근 제어
- 특정 샤드에 접근 권한을 설정함으로써, 데이터 접근 제어가 보다 세밀하게 가능해집니다.
- 예: VIP 고객 데이터를 별도 샤드에 분리하고 접근 제어 적용.

---

## ❌ 단점

### 1. 클라이언트 복잡도 증가
- 클라이언트가 어떤 데이터가 어떤 샤드에 있는지 알아야 하므로, **비즈니스 로직이 복잡해집니다**.
- 이를 해결하기 위해 일관된 해싱(Consistent Hashing)을 사용하지만, 완전한 추상화는 어렵습니다.

### 2. 샤드 간 트랜잭션의 어려움
- 여러 샤드에 걸친 **원자적 트랜잭션**은 거의 불가능합니다.
- 롤백 처리도 매우 복잡하고, 실패 시 데이터 불일치 가능성이 있습니다.

### 3. 스키마 변경의 어려움
- 모든 샤드에 대해 동일한 스키마 변경을 적용해야 하므로, **관리 부담이 큽니다**.
- 일부 샤드에만 변경이 적용되면, 시스템 전반에 문제를 야기할 수 있습니다.

### 4. 조인(JOIN) 연산의 제약
- 샤드 간 데이터를 조인하기 어렵기 때문에, **복잡한 쿼리 작성이 제한**됩니다.
- 조인을 수행하려면 어플리케이션 레벨에서 데이터를 수집하고 병합해야 하는 경우도 있음.

### 5. 샤딩 키 외의 조건으로 쿼리할 경우 비효율
- 샤딩 키가 아닌 필드로 검색하면, **모든 샤드를 순회**해야 할 수 있어 성능이 저하됩니다.
- 예: 고객 이름으로 검색 시, 이름이 샤딩 키가 아니면 전체 샤드를 스캔해야 함.

---

## 📌 마무리

샤딩은 **대용량 데이터 처리와 시스템 확장에 매우 효과적인 기술**이지만, 그만큼 **운영과 설계가 복잡해지는 단점**도 존재합니다. 샤딩이 적합한지 여부는 **데이터의 분포, 트래픽 패턴, 트랜잭션 요구사항** 등을 종합적으로 고려해서 판단해야 합니다.
